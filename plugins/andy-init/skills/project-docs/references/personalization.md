# 個人化：問答、習慣檔、結構調整

> 步驟 0 的完整程序。SKILL.md 只寫「要問」，這裡寫「問完之後怎麼處理」。
>
> 一條總原則貫穿本檔：**使用者的習慣優先於本 skill 的預設**，
> 但代價要講出來。照做不等於不提醒。

---

## 一、怎麼問

用 `AskUserQuestion` 一次問完，不要一題一題來。三題的實際措辭：

**Q1 這個專案要哪幾份文件？**

| 選項 | 內容 |
|---|---|
| 四份骨幹（建議） | PRD / ARCHITECTURE / ROADMAP / PROGRESS + AGENTS.md／CLAUDE.md |
| 精簡三份 | AGENTS.md／CLAUDE.md + ARCHITECTURE + PROGRESS（小專案、一個人做） |
| 自己挑 | 逐份確認，並當場講出每個「不要」的代價（見第三節） |

**Q2 你的工程習慣從哪來？**

| 選項 | 後續動作 |
|---|---|
| 給檔案路徑 | 讀完整份再動手（見第二節） |
| 我直接講 | 記下原句，**不要改寫措辭**，再問「這些是跨專案通用還是只有這個專案」 |
| 沿用現有 AGENTS.md／CLAUDE.md | 先讀專案與使用者層的 AGENTS.md 與 CLAUDE.md，把既有規則當既成事實，只補不改；規則若寫在 CLAUDE.md，搬進 AGENTS.md（措辭不改） |
| 沒有，用預設 | 照本 skill 走，結尾提一句「之後想套自己的習慣可以再叫我」 |

**Q3 要存成跨專案預設嗎？**

要 → 寫 `~/.claude/project-docs.preferences.md`（格式見第五節）。
只用這次 → 不寫檔，但在本次產出的 AGENTS.md 裡留下實際採用的結構。

### 什麼時候不要問

- 使用者已經講明的那一題**不要再問**。他說「不要 PROGRESS.md」就只問剩下的。
- 答「都好」「你決定」→ 用四份骨幹，**不追問第二次**。
- 非互動環境 → 用預設做完，結尾說明用了哪些預設、怎麼改。
- 偏好檔已存在 → 一行複述 + 給反悔機會，不重跑問答。

## 二、收到習慣檔怎麼處理

### 1. 整份讀完再動手

不要只看標題或前 30 行就開始分類。習慣檔的後段常常是最具體的條目
（commit 格式、語言要求、禁用 API），而那些正是要原封不動搬進 AGENTS.md 的東西。

### 2. 逐條分類：跨專案通用，還是本專案特有

| 類型 | 判準 | 去哪 |
|---|---|---|
| 跨專案通用 | 換一個 repo 也成立（證據標準、commit 格式、語言、資料誠實性） | **使用者層**，專案只留一行指針 |
| 本專案特有 | 提到具體的表名、埠號、資料源、目錄 | 專案 `AGENTS.md` |
| 其實是描述不是規則 | 「X 層負責 Y」 | `ARCHITECTURE.md` |
| 其實是 reference | 欄位、API 清單、schema | `docs/` 下的模組檔，標「被指引才讀」 |

🔴 **跨專案的習慣不要複製進每個 repo。** 複製 N 份就是 N 份會各自漂移，
改一條要記得改 N 個地方——而沒有任何機制會提醒你漏了哪一個。

使用者層的兩種放法（Claude Code 只自動載入 `~/.claude/CLAUDE.md`，所以它一定要存在，但只當殼）：

```markdown
# 放法 A：寫進 ~/.claude/AGENTS.md，~/.claude/CLAUDE.md 只放 @~/.claude/AGENTS.md
（andy-init 的 /andy-init:setup 就是這樣裝的）

# 放法 B：原檔保留自己的檔名（例如 ~/.claude/ENGINEERING.md），
# 由 ~/.claude/AGENTS.md 用一行 @~/.claude/ENGINEERING.md 引入
```

兩種放法的共同點：**規則本體在 AGENTS.md 這一側，CLAUDE.md 永遠只是 import 殼。**
已經跑過 `/andy-init:setup` 的機器用 A，不要再疊一份。

專案 `AGENTS.md` 開頭則只留一行指針，讓讀到專案文件的人知道還有上一層：

```markdown
> 跨專案的工程習慣在 `~/.claude/AGENTS.md`（每個 session 自動載入）。
> 本檔只寫這個專案特有的約束。
```

### 3. 只留「違反就直接影響產出」的條目

習慣檔裡的心法（「要有工程素養」）不進 AGENTS.md——沒有可檢查的違反條件，
它只會稀釋周圍那些真的要遵守的條目。

### 4. 不要改寫使用者的措辭

那是他的規則，照搬。可以做的只有三件事：**去重**、**分類**、
**把同一件事的兩處合併成一處並標明權威在哪**。
把「永不無聲降級」改成「應盡量告知使用者」這種軟化，是在改變規則本身。

### 5. 衝突停下來講清楚

習慣檔與本 skill 衝突 → 照習慣檔，講一句代價。真實例子：

| 習慣檔說 | 本 skill 說 | 怎麼辦 |
|---|---|---|
| 複雜任務在 `docs/` 建實體追蹤檔 | 實作計畫不要落成檔案 | 建，但講明完成後要 `git rm`，否則會長成第二份 PROGRESS |
| 長文件開頭放「§0 接手速覽」 | 新 session 從 PROGRESS.md 開始 | 兩者相容：PROGRESS 開頭就是 `§0 接手速覽`（範本已內建）；其他文件超過 300 行才另放，不要每份都放一段 |
| 進度符號固定 ⬜／🔄／✅／⛔ | （無規定） | 範本已採用；PROGRESS 的「進度」表與 ROADMAP 的「現況」一律用這四個 |
| 文件數量固定、禁止同義檔增生 | 條件成立時可加 HISTORY / OPERATIONS | 先問「既有哪一份不能承擔」，問不出答案就不加 |

習慣檔內部自相矛盾（後面的章節推翻前面的）→ **問使用者，不要自己選一邊。**

## 三、砍掉某一份的代價

使用者要精簡時，先把代價講出來再動手。**不是勸退，是讓他知道自己在換掉什麼。**

| 砍掉 | 職責由誰接手 | 代價 |
|---|---|---|
| `PROGRESS.md` | 沒有人 | 骨幹裡最常讀的一份。砍掉後新 session 要靠 `git log` 重建現況。砍它之前先問：是真的不需要，還是只是嫌它要維護？後者的解法是寫短，不是砍掉 |
| `ROADMAP.md` | PRD 的「非目標」+ PROGRESS 的「下一步」 | 中期方向沒地方放，通常會回流成 `TODO.md`。一個人做的小專案可接受 |
| `PRD.md` | AGENTS.md 開頭的定位段 | 「什麼算完成」變成口耳相傳，驗收標準每次重新發明。內部工具、需求穩定時可接受 |
| `ARCHITECTURE.md` | 程式碼本身 + AGENTS.md 的規則 | 單一資料源的小專案可行；一旦有兩個以上資料源或非同步流程就會後悔 |
| `AGENTS.md` + `CLAUDE.md` | **不可砍（成對）** | AGENTS.md 是規則本體，CLAUDE.md 是讓它每個 session 自動載入的唯一入口。砍任何一個，陷阱與硬性約束就不生效 |

### 砍掉之後必做

1. **改 AGENTS.md 的文件索引表**——刪掉那一列，不留指向不存在檔案的連結。
2. **改其他文件的互相指路**——範本開頭那些「怎麼做看 ARCHITECTURE.md」要跟著改。
3. **把職責併進接手的那一份**，並在該檔開頭寫明它現在多管了什麼。
4. **重跑一次連結檢查**：

   ```bash
   grep -rhoE "\]\(([A-Z_]+\.md)\)" docs/*.md AGENTS.md | sort -u
   ```

5. **數字要一致**——AGENTS.md 寫「文件只有 N 份」時，N 要跟實際份數相同。
   數字型描述沒有任何機制會提醒你它過期了。

## 四、要多加一份的時候

使用者點名要本 skill 禁建清單上的檔案（`TASKS.md`、`DECISIONS.md`……）→ **建。**
只做兩件事：

1. 講明它與哪一份重疊、重疊的部分以哪一份為權威。
2. 講明它的**結束條件**——什麼時候該 `git rm`。沒有結束條件的追蹤文件
   會一路長到沒人敢刪。

寫進 AGENTS.md 的索引表時，第三欄「什麼時候讀」照樣不可省。

## 五、偏好檔格式

路徑固定 `~/.claude/project-docs.preferences.md`。
放在 skill 目錄外，重裝 skill 不會被蓋掉。

```markdown
# project-docs 偏好

**最後更新：YYYY-MM-DD**

## 文件結構

| 檔案 | 要不要 | 備註 |
|---|---|---|
| `AGENTS.md` | 要 | 規則本體，不可砍 |
| `CLAUDE.md` | 要 | 只放 `@AGENTS.md`，不可砍 |
| `docs/PRD.md` | 要 | |
| `docs/ARCHITECTURE.md` | 要 | |
| `docs/ROADMAP.md` | 不要 | 方向併進 PRD 非目標與 PROGRESS 下一步 |
| `docs/PROGRESS.md` | 要 | |

## 工程習慣

來源：`~/.claude/AGENTS.md`，由 `~/.claude/CLAUDE.md` import。
**跨專案共用，不複製進 repo。** 專案 AGENTS.md 只留一行指針。

## 文件同步 hook

要（或「不要」）。決定 init／migrate／audit 時是否安裝 `.claude/hooks/docs-sync.cjs`。

本 skill 的預設中，已被上述習慣覆蓋的條目：
- 「實作計畫不要落成檔案」→ 改為複雜多階段任務建實體追蹤檔（完成後 `git rm`）

## 每次都要做的

- 一律繁體中文；技術識別字保留原文
- 動手前先確認要哪幾份，不要直接開檔
```

第三節「已被覆蓋的預設」是這份檔案最有價值的一段——
下一個 session 讀到它才不會又把使用者的決定改回本 skill 的預設。

### 更新時機

- 使用者這次的選擇與偏好檔不同 → 問「要更新偏好檔嗎」，不要默默改。
- 偏好檔提到的路徑不存在了（習慣檔被搬走）→ **當場講出來**，不要假裝讀到了。
